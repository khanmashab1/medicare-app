Here's a complete spec for the Appointment booking flow so you can build the mobile app cleanly against your existing Supabase backend (`zikbiesawrowlkhvrbmz`). --- 1. Database tables you'll touch `profiles` (read patient info) - `id` (uuid, = auth user id) - `name`, `phone`, `email`, `blood_type`, `city`, `date_of_birth`, `patient_id` `doctors` (read doctor catalog) - `user_id` (uuid) — joins to `profiles.id` for doctor's name - `specialty`, `degree`, `qualifications`, `bio` - `fee`, `consultation_duration` (min), `delay_minutes` - `city`, `province`, `clinic_address`, `image_path` - `rating`, `experience_years`, `max_patients_per_day` - `easypaisa_number`, `jazzcash_number`, `bank_*` (for online payment display) `doctor_schedules` (working hours) - `doctor_user_id`, `day_of_week` (0=Sun…6=Sat), `start_time`, `end_time`, `is_available` `doctor_breaks` (lunch/prayer breaks) - `doctor_user_id`, `start_time`, `end_time`, `applies_to_days[]`, `is_active` `blocked_slots` (off days/leaves) - `doctor_user_id`, `blocked_date`, `blocked_time` (nullable = full day) `appointments` (the booking itself) - `patient_user_id`, `doctor_user_id`, `appointment_date` (date), `token_number` (int) - `patient_full_name`, `patient_phone`, `patient_email` - `reason`, `department` - `payment_method` ('Cash' | 'Online'), `payment_status` ('NA' | 'Pending' | 'Verified') - `receipt_path` (storage path for online payments) - `status` — one of: `Pending`, `Upcoming`, `In Progress`, `Completed`, `Cancelled`, `No Show` --- 2. Booking rules (enforced in DB — don't reimplement) - One active appointment per patient per doctor per day — `allocate_token` RPC raises an error. - Max patients/day comes from `doctors.max_patients_per_day` minus blocked slots. - Token allocation is atomic via `allocate_token(p_doctor_id uuid, p_date date)` → returns next token number. --- 3. The 5-Step flow → exact queries Step 1 — Location ```ts // Distinct provinces const { data } = await supabase.from('doctors').select('province').not('province','is',null); // Then cities filtered by province const { data } = await supabase.from('doctors').select('city').eq('province', province); ``` De-duplicate client-side. Step 2 — Specialty (with doctor counts) Use your backend proxy (since RLS hides `doctors` from anon). Endpoint should run: ```sql SELECT specialty, COUNT(*) AS doctor_count FROM doctors WHERE city = $1 AND province = $2 GROUP BY specialty; ``` Step 3 — Doctor list Proxy endpoint: ```sql SELECT d.user_id, p.name, d.specialty, d.degree, d.qualifications, d.bio, d.fee, d.rating, d.experience_years, d.image_path, d.city, d.clinic_address, d.consultation_duration, d.easypaisa_number, d.jazzcash_number, d.bank_name, d.bank_account_number, d.bank_account_title FROM doctors d JOIN profiles p ON p.id = d.user_id WHERE d.city = $1 AND d.specialty = $2; ``` Step 4 — Date & Token grid For the selected date: a) Get already-booked tokens: ```ts const { data: booked } = await supabase .from('appointments') .select('token_number, status') .eq('doctor_user_id', doctorId) .eq('appointment_date', dateISO) .neq('status', 'Cancelled'); ``` b) Get blocked slots: ```ts const { data: blocked } = await supabase .from('blocked_slots') .select('blocked_time') .eq('doctor_user_id', doctorId) .eq('blocked_date', dateISO); ``` c) Compute available count: ```ts const { data } = await supabase.rpc('get_available_slots', { p_doctor_id: doctorId, p_date: dateISO }); ``` Render token grid `1..max_patients_per_day`. Mark booked numbers as taken. Payment method: radio Cash / Online (Easypaisa). If Online, show the doctor's `easypaisa_number` and let user upload a receipt screenshot to the `receipts` storage bucket → save returned path to `receipt_path`. Step 5 — Confirm & submit ```ts // 1) Allocate token atomically (server validates one-per-day rule) const { data: token, error: tokenErr } = await supabase.rpc('allocate_token', { p_doctor_id: doctorId, p_date: dateISO, }); if (tokenErr) throw tokenErr; // shows "already booked" or "no slots" // 2) Insert appointment const { error } = await supabase.from('appointments').insert({ patient_user_id: user.id, doctor_user_id: doctorId, appointment_date: dateISO, token_number: token, patient_full_name: profile.name, patient_phone: profile.phone, patient_email: profile.email, reason, department: specialty, payment_method: paymentMethod,           // 'Cash' or 'Online' payment_status: paymentMethod === 'Online' ? 'Pending' : 'NA', receipt_path: receiptPath ?? null, status: 'Pending',                        // PA confirms → 'Upcoming' }); ``` > Lifecycle: `Pending` → PA verifies → `Upcoming` → doctor sees patient → `In Progress` → `Completed`. Patient can cancel only while `Pending` or `Upcoming`. --- 4. Appointments list queries ```ts // All for current patient supabase.from('appointments') .select('*') .eq('patient_user_id', user.id) .order('appointment_date', { ascending: false }); ``` Filter client-side by tab (`Upcoming`, `Completed`, `Cancelled`, `Pending`). Cancel: ```ts supabase.from('appointments') .update({ status: 'Cancelled' }) .eq('id', appointmentId) .eq('patient_user_id', user.id);   // RLS also enforces ``` Doctor name for each card — join via a second query or your proxy: ```sql SELECT a.*, p.name AS doctor_name, d.specialty FROM appointments a JOIN profiles p ON p.id = a.doctor_user_id LEFT JOIN doctors d ON d.user_id = a.doctor_user_id WHERE a.patient_user_id = $1; ``` --- 5. Prescription screen Use the existing public RPC (no auth required, safe by design): ```ts const { data, error } = await supabase.rpc('get_prescription_verification', { p_appointment_id: appointmentId, }); ``` Returns a single JSON with: patient info, diagnosis, `medicines` (string — parse with your existing `formatMedicinesText` logic), `lab_tests`, `doctor_comments`, vitals, doctor name/specialty/degree/city. QR code value = `https://medicareplus.app/verify/${appointmentId}`. --- 6. Auth setup for Expo ```ts import 'react-native-url-polyfill/auto'; import AsyncStorage from '@react-native-async-storage/async-storage'; import { createClient } from '@supabase/supabase-js'; export const supabase = createClient( 'https://zikbiesawrowlkhvrbmz.supabase.co', '', { auth: { storage: AsyncStorage, autoRefreshToken: true, persistSession: true, detectSessionInUrl: false, }, } ); ``` RLS on `appointments` already allows: `patient_user_id = auth.uid()` for select/insert/update — so no extra policies needed for the patient app. --- 7. What you must NOT do client-side - ❌ Don't call admin/PA-only tables (`pa_assignments`, `email_logs`, etc.). - ❌ Don't bypass `allocate_token` — race conditions will give two patients the same token. - ❌ Don't compute "available specialties/doctors" by selecting from `doctors` directly with the anon key — RLS blocks it.
